# Ржавчина на листьях: обучение и проверка модели

Приложение для агрономов: обучить нейросеть находить ржавчину на фото листьев кофе и применить её к новым снимкам.
Открывается в браузере, программировать не нужно. Прототип экранов лежит в `prototype/index.html`.

Сценарий лабораторного практикума «разметка → обучение» и подготовка учебных ПК — в [PRACTICUM.md](PRACTICUM.md).

## Запуск

```bash
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt    # для видеокарты NVIDIA поставьте torch по инструкции pytorch.org
python app.py
```

На занятиях с данными в папках запускайте `RUST_ALLOW_LOCAL_PATHS=1 python app.py` (в Windows: `set RUST_ALLOW_LOCAL_PATHS=1`), см. раздел про локальный режим ниже.

Браузер откроется сам (адрес http://127.0.0.1:8765). Для выбора папок кнопкой «Обзор…» нужен tkinter
(Linux: `sudo apt install python3-tk`). Интерфейс уже собран в `web/dist`, Node.js для запуска не нужен.

Данные лежат рядом с программой: `train/`, `valid/`, `test/` (фото `.jpg` и маски `.png` с тем же именем,
допустим суффикс `_mask`). Результаты обучения сохраняются в `OUT/<имя эксперимента>/`
(другая папка: переменная `RUST_OUT_DIR`).

## Серверный режим (общий сервер)

Приложение можно запустить один раз на сервере, а пользователям достаточно браузера: они входят по токену,
загружают свои фото, учат модель в общей очереди и скачивают результат. Ставить Python и клонировать репозиторий им не нужно.

```bash
cp .env.example .env               # задайте RUST_TOKEN (и RUST_BASE_PATH, если нужен подпуть)
docker compose up -d --build
```

Что получают пользователи:

- **Вход по токену.** Один общий токен `RUST_TOKEN`, его выдаёт администратор. Без токена сервер открыт всем, поэтому на сети его задавать обязательно.
- **Свои данные.** Фото и маски (`.jpg`, `.png`) или один zip с папками `train/valid/test` загружаются кнопкой на шаге «Данные». Каждый браузер получает личное пространство, чужие данные не видны.
- **Очередь обучения.** Одновременно учится столько моделей, сколько задано в `RUST_MAX_PARALLEL` (по умолчанию 1), остальные ждут и видят своё место. Страницу можно закрыть.
- **Результаты.** Скачиваются модель (`.pth`) и все файлы эксперимента (zip). Готовые модели из `OUT/` (смонтированы как `/models`) видны всем только для чтения: их можно применять к фото или сравнивать.

### Подпуть и HTTPS

Интерфейс собран с относительными адресами, поэтому работает и в корне сайта, и под префиксом, например `https://host/kofi/`.
Укажите префикс в `RUST_BASE_PATH=/kofi`. Прокси может как отрезать префикс, так и передавать его как есть, оба варианта работают.

```nginx
location /kofi/ {
    proxy_pass http://127.0.0.1:8765;   # без слэша на конце: префикс передаётся как есть (с / на конце он отрезается, тоже работает)
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_buffering off;                 # нужно для потока прогресса обучения (SSE)
    client_max_body_size 1g;             # размер загрузки данных, см. RUST_MAX_UPLOAD_MB
    proxy_read_timeout 1h;
}
```

### Настройки (переменные окружения)

| Переменная | Назначение |
|---|---|
| `RUST_TOKEN` | общий токен доступа; не задан: вход без пароля |
| `RUST_BASE_PATH` | префикс адреса, например `/kofi` |
| `RUST_DATA_DIR` | рабочие папки пользователей (по умолчанию `data/`, в Docker `/data`) |
| `RUST_OUT_DIR` | готовые общие модели, только чтение (по умолчанию `OUT/`) |
| `RUST_MAX_PARALLEL` | сколько обучений одновременно (1) |
| `RUST_REQUIRE_GPU` | `1`: не начинать обучение без видеокарты (в `docker-compose.yml` включено) |
| `RUST_MAX_UPLOAD_MB`, `RUST_MAX_WORKSPACE_MB` | лимит одной загрузки (1024) и данных одного пользователя (4096) |
| `RUST_ALLOW_LOCAL_PATHS` | `1`: локальный режим, см. ниже |
| `HOST`, `PORT` | адрес сервера (по умолчанию `127.0.0.1:8765`) |

### Видеокарта (GPU)

По умолчанию образ собирается с torch под CUDA 12.9, и `docker-compose.yml` отдаёт контейнеру одну видеокарту NVIDIA.
На хосте нужны только драйвер NVIDIA (525 и новее) и [nvidia-container-toolkit](https://docs.nvidia.com/datacenter/cloud-native/container-toolkit/latest/install-guide.html); CUDA ставить не нужно, она входит в образ (он весит около 8 ГБ).

Проверить, что карта видна контейнеру:

```bash
docker compose exec rust python -c "import torch; print(torch.cuda.get_device_name(0))"
```

В интерфейсе внизу слева будет написано «Видеокарта» и её название. Если карта недоступна, обучение не стартует и пользователь видит сообщение (`RUST_REQUIRE_GPU=1` в compose), а не тихо уходит на процессор.

- Старая карта или драйвер: `TORCH_INDEX=https://download.pytorch.org/whl/cu126` в `.env`. Драйвер 580 и новее: `.../whl/cu130`.
- Сервер без видеокарты: `docker compose -f docker-compose.cpu.yml up -d --build` (образ около 2 ГБ, обучение на процессоре).
- Используется одна карта (первая). `RUST_MAX_PARALLEL` оставьте равным 1: два обучения одновременно делят память карты и могут упасть с нехваткой памяти. Если видеопамяти не хватает, уменьшите размер изображения или batch на шаге «Параметры».
Личные пространства сами не удаляются: старые папки в `RUST_DATA_DIR/workspaces/` чистите вручную.

### Занятия на своём компьютере (папки вместо загрузки)

Для практикума на станциях, где данные лежат в папках, включите локальный режим: `RUST_ALLOW_LOCAL_PATHS=1 python app.py`.
На шаге «Данные» вернутся поля путей и кнопка «Обзор…», результаты пишутся в `OUT/`. На общем сервере этот режим не включайте:
пользователь сможет читать любые папки на нём.

## Структура

| Папка | Что внутри |
|---|---|
| `core/` | Вычислительное ядро: данные, обучение, применение модели, чтение экспериментов. Перенесено из `train_gui.py` и `infer_rust.py` без изменения алгоритмов |
| `server/` | FastAPI: API для интерфейса (`/api/...`), прогресс обучения по SSE, раздача `web/dist` |
| `web/` | Интерфейс: Vite, React, TypeScript (strict), zustand, ESLint. Структура FSD: `app, pages, widgets, features, entities, shared` |
| `prototype/` | Согласованный кликабельный макет (HTML) |
| `app.py` | Точка входа |
| `train_gui.py`, `infer_rust.py` | Старые Tkinter-программы, оставлены для сравнения |

## Разработка интерфейса

```bash
python app.py --no-browser         # сервер на :8765
cd web && npm install && npm run dev   # http://localhost:5173, /api проксируется на сервер
npm run lint && npm run build          # проверка и сборка в web/dist (папку dist нужно коммитить)
```

Правило FSD проверяет ESLint: нижние слои не импортируют верхние.

## Что осталось доделать

- Оценки «Отлично / Хорошо / Можно лучше» (`web/src/shared/lib/format.ts`) заданы по порогам 75% и 65% IoU. Пороги предложены для обсуждения.
- Время обучения на экране «Параметры» оценивается грубой формулой (`estimateMinutes`). Заменить реальным замером.
- В «Проверить фото» загружаются только фото без масок: сравнение с разметкой эксперта доступно для экспериментов (экран «Результаты»), но не для загруженных снимков.
- Результаты проверки не пишутся на диск, их можно скачать в CSV. Старый `infer_rust.py` сохранял маски и наложения в `OUT_test/`.
- Модели из статьи (YOLOv8, SAM2 в отдельной папке) в интерфейс не подключены.
- Проверено на macOS и Python 3.13. Windows и Linux не проверялись; обучение с видеокартой не проверялось.
