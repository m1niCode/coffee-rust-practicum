# Практикум «Разметка → обучение»: ржавчина на листьях кофе

**Длительность:** 2 часа. **Аудитория:** биотехнологи и агрономы, программировать не нужно.
**Итог занятия:** участники сами размечают пятна, видят, как разметка становится датасетом,
обучают нейросеть сегментации и сравнивают свои эксперименты по качеству.

Данные — открытый датасет к статье (github.com/MaryPazRB/paper_CLR_CV): вырезанные листья кофе
и маски пятен ржавчины (*Hemileia vastatrix*), 405 / 101 / 100 снимков (train / valid / test).

---

## Подготовка (накануне, ~1 час на ПК)

| Шаг | Команда | Что проверить |
|---|---|---|
| 1. Код | `git clone … && git checkout feature/new-ui` | есть `web/dist/index.html` |
| 2. Данные | скопировать `train/`, `valid/`, `test/`, `OUT/` (с `.pth`) в папку проекта | они не хранятся в git |
| 3. Установка | `bash setup_ubuntu.sh` (без NVIDIA: `--cpu`) | в конце «Всё готово к занятию» |
| 4. Без интернета | `.venv/bin/python check_env.py --offline` | веса ImageNet есть в кэше |
| 5. Пробный запуск | `source .venv/bin/activate && RUST_ALLOW_LOCAL_PATHS=1 python app.py`, обучить 1 эпоху | браузер открыл `http://127.0.0.1:8765` |

`setup_ubuntu.sh` ставит три изолированных окружения (`.venv` — обучение, `.venv-labelme`,
`.venv-ls`), собирает набор для разметки `practicum/label_set/` и мини-датасет `practicum/data_mini/`.
`check_env.py` в конце замеряет скорость: если 8 эпох мини-датасета дольше ~15 минут (так бывает
без видеокарты), уменьшите мини-датасет (`tools/make_mini_dataset.py --train 80 --valid 20 --test 20`)
и уберите из таблицы экспериментов D и E.

**Распределите заранее:** каждому участнику 2–3 листа из `leaf_01…leaf_10` и одну конфигурацию
из таблицы экспериментов (этап 4). Листья 04 и 10 сняты иначе (светлый лист, бледные старые пятна) —
на них участники, скорее всего, сильнее разойдутся с экспертом; дайте каждый хотя бы двум людям, чтобы
было что обсудить.

### 1. Введение (15 мин) — показывает ведущий

1. **Задача:** доля поражённой площади листа — стандартная оценка тяжести ржавчины. Глазом её
   оценивают баллами, и у разных экспертов они расходятся; нейросеть считает долю в пикселях одинаково.
2. **Пайплайн:** фото поля → вырезанный лист → разметка пятен → обучение → модель → доля поражения.
   (В статье лист вырезает YOLOv8, а пятна сегментирует SAM2; на практикуме мы обучаем U-Net
   только на втором шаге.)
3. **Виды разметки** — на примере ExpertScore (без углубления):
   - *классификация / оценка по карточкам* — «есть ржавчина: да/нет», балл 0–5; быстро, но без площади;
   - *рамки (detection)* — каждое пятно в прямоугольнике; можно посчитать пятна, площадь — грубо;
   - *ключевые точки* — для формы и поз, здесь не нужны;
   - *маска (сегментация)* — каждый пиксель «пятно / не пятно»; только она даёт точную площадь.
     Поэтому дальше работаем в открытых программах для масок.
4. **Открытые программы для масок:** labelme (на ПК, без сервера), Label Studio (в браузере, удобно
   группе), CVAT (промышленная, нужен Docker — только упомянуть).

### 2. Разметка (30 мин)

Основной вариант — **labelme**; Label Studio — альтернатива (группе, у которой labelme не запустился,
или для сравнения инструментов).

**labelme** (из папки проекта):

```bash
.venv-labelme/bin/labelme practicum/label_set/images --labels practicum/labelme_labels.txt --nodata --autosave
```

- `Ctrl+N` — полигон: кликами обвести пятно, замкнуть на первой точке, метка `rust`.
- Колесо + `Ctrl` — масштаб. `D` / `A` — следующий / предыдущий лист. Сохраняется само (`--autosave`),
  рядом с фото появится `leaf_XX.json`.
- Каждое пятно — отдельный полигон. Мелкие точки размером в несколько пикселей можно пропустить —
  это хороший повод обсудить, где граница между «пятном» и «шумом».

**Label Studio** (альтернатива):

```bash
.venv-ls/bin/label-studio start --port 8080
```

1. Браузер → создать локальную учётку → *Create Project*.
2. *Data Import* — перетащить фото из `practicum/label_set/images`.
3. *Labeling Setup → Custom template → Code* — вставить `practicum/label_studio_config.xml`.
4. Размечать полигоном (`P`) или кистью (`B`, ластик `E`), *Submit*.
5. *Export → JSON* — сохранить файл.

**Из разметки — в маски** (одинаково для обеих программ):

```bash
source .venv/bin/activate
# labelme:
python tools/annotations_to_masks.py practicum/label_set/images --out practicum/my_masks
# Label Studio:
python tools/annotations_to_masks.py ~/Загрузки/project-1-at-*.json --images practicum/label_set/images --out practicum/my_masks
```

**Сравнение с экспертом:**

```bash
python tools/compare_masks.py practicum/my_masks
```

Открыть `practicum/my_masks/compare/*.jpg`: **жёлтое** — совпало, **зелёное** — эксперт отметил,
вы нет, **красное** — отметили только вы.

**Обсуждение (5 мин):** у кого какой IoU с экспертом? Он будет заметно ниже 1: люди тоже расходятся,
особенно по краям пятен и мелким точкам. Сравните с IoU готовых моделей (~0.7 на test). Это «потолок» для модели: она учится на разметке
и не может быть точнее неё. А на один лист ушло 2–4 минуты — значит, на 400 листьев нужно
больше 15 часов работы эксперта.

### 3. Данные (10 мин)

Запустить приложение: `RUST_ALLOW_LOCAL_PATHS=1 python app.py` (режим с папками) → «Обучить модель» → шаг «Данные».
Указать папки `practicum/data_mini/train`, `…/valid`, `…/test` → «Проверить данные».

Разобрать:
- **train** (150) — на них сеть учится; **valid** (40) — по ним после каждой эпохи выбирается лучшая
  модель; **test** (40) — честная итоговая оценка, используется один раз.
- Маска — это картинка, где 1 = пятно. На листе в среднем всего ~3 % пикселей ржавчины, поэтому
  «точность по пикселям» бесполезна (сеть, которая везде отвечает «здоров», была бы права на 97 %).
  Отсюда метрики **IoU** и **Dice**: доля совпадения выделенной области.
- В датасете 14 листьев с пустой маской — здоровые; они нужны, чтобы сеть не находила пятна везде.
- **Особенности, найденные при подготовке:** в test пятен вдвое больше (5.9 % против 2.5 % в train)
  и снимки не растянуты до квадрата — проверка на «чужих» данных строже; некоторые листья в train
  и valid вырезаны из одного и того же исходного фото, поэтому оценка на valid слегка завышена.

### 4. Параметры и обучение (30 мин)

Шаг «Параметры» → выбрать набор **«Быстро»**: он и есть базовая настройка. Затем изменить только
поле своего эксперимента (кнопки ± у числа эпох меняют его на 5).

| Поле | Значение |
|---|---|
| Тип нейросети / основа | Unet / resnet18 |
| Готовые знания (ImageNet) | вкл. |
| Подробность снимков | 256 |
| Число эпох / ранняя остановка | 8 / 0 (выкл.) |
| Фото за один шаг | 8 |
| Скорость обучения | 0.001 |
| Разнообразие данных | все три вкл. |
| Порог / вес Dice / seed | 0.5 / 0.5 / 42 |

**Эксперименты** — каждый участник или пара берёт одну строку; в «Название эксперимента» —
код строки и фамилия (например, `B_ivanov`):

| Код | Что меняем | Вопрос, на который отвечает |
|---|---|---|
| A | ничего (базовая) | точка отсчёта |
| B | Готовые знания — выкл. | зачем нужна предобученная сеть |
| C | Разнообразие данных — выкл. | помогают ли аугментации на малых данных |
| D | Подробность 384 | видны ли мелкие пятна лучше; во сколько раз дольше |
| E | Основа resnet34 | помогает ли более крупная сеть |
| F | Тип FPN | другая архитектура |
| G | Скорость обучения 0.01 | что будет при слишком большом шаге |
| H | Эпох 3 (кнопка «−») | недообучение |
| I | Базовая, но train = `practicum/data_mini_plus/train` | меняют ли что-то свои размеченные листья |
| J | Базовая, seed 7 | разброс от случая: какую разницу между A–I вообще можно считать реальной |
| K | Эпох 18 (кнопка «+» дважды) | хватило ли базовой модели 8 эпох |

**Ориентир (проверено при подготовке, процессор без видеокарты):** базовая настройка A обучается
за ~2 минуты, IoU на valid 0.68, на test 0.53. К 8-й эпохе IoU ещё растёт, поэтому K, скорее всего,
окажется лучше. Готовые `exp1`–`exp3` дают на test ~0.70: в 2,7 раза больше данных, 384–512 px, 10–100 эпох.
Обучение быстрое, так что за этап каждый успеет 2–3 эксперимента.

Для строки I ведущий заранее (или во время этапа 2) собирает датасет с масками участников:

```bash
python tools/make_mini_dataset.py --out practicum/data_mini_plus --extra practicum/my_masks
```

Пока идёт обучение, на экране «Обучение» видно журнал и кривые. Что обсудить в это время:
- **эпоха** — один проход по всем фото; **потери** должны падать, **IoU на valid** — расти;
- если потери train падают, а valid растут — это **переобучение** (запоминание вместо обобщения);
- почему сеть на видеокарте учится в десятки раз быстрее, чем на процессоре.

### 5. Результаты (20 мин)

Экран «Результаты»:
- кривые потерь и IoU по эпохам, примеры «фото / разметка / модель» на valid и test;
- отметить несколько экспериментов, включая готовые `exp1`–`exp3` (полный датасет, 512 px, 50–100 эпох;
  IoU на test ≈ 0.68–0.70), и сравнить.

Экран «Проверить фото»:
- загрузить 3–5 фото из `test/` или свои снимки листьев, выбрать модель;
- подвигать **порог уверенности**: ниже — находит больше, но и ложных пятен больше;
- скачать CSV с долей поражения по каждому листу — это и есть результат для агронома.

### 6. Итоги (15 мин)

Собрать на доске таблицу: код эксперимента → IoU на test → время обучения. Типичные выводы
(проверьте на своих результатах, а не зачитывайте):
1. Предобученная сеть (A против B) — самый большой выигрыш на малых данных.
2. Размер снимка (D) важен для мелких пятен, но обходится заметно дольше.
3. Слишком большой шаг обучения (G) или мало эпох (H) портят результат сильнее, чем выбор архитектуры.
4. Разница меньше, чем между A и J (seed), — это шум, а не эффект.
5. Модель не бывает точнее разметки: расхождение людей на этапе 2 — её предел.
   Больше данных и согласованная разметка дают больше, чем подбор параметров.

## Шпаргалка ведущего

| Проблема | Решение |
|---|---|
| labelme не открывается (ошибка `xcb`) | `sudo apt install libxcb-xinerama0 libxcb-cursor0`; иначе — Label Studio |
| В маске пятна не там | проверить, что JSON от того же фото; `--label rust`, если были лишние метки |
| «Не удалось загрузить предобученные веса» | на ПК без интернета не прогрет кэш — `check_env.py` с интернетом |
| CUDA out of memory | уменьшить «Фото за один шаг» до 4 или размер до 256 |
| Обучение слишком долгое | эпох 3; мини-датасет меньше (`--train 80`); в крайнем случае показать готовые `exp1`–`exp3` |
| Порт 8765 занят | приложение уже запущено — открыть `http://127.0.0.1:8765` |
